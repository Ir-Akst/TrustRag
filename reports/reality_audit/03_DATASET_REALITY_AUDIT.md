## 2. Critical Provenance & Quality Findings

### A. `custom_security` is 100% Cyclic Template Synthetic Data
Direct inspection of [security_generator.py](file:///c:/Users/Dell/Desktop/trustrag/src/trustrag/data/benchmarks/security_generator.py#L28-L150) confirms that all `2,000` records in `data/raw/custom_security/raw_train.jsonl` (`1,000` clean / `1,000` poisoned across 6 attack families) are deterministically generated by cycling **`_TEMPLATES[i % 8]`**—just **8 base templates**—with `f"[{topic} - Item {variation}] "` prepended to clean and poisoned passages (`provenance: "TrustRAG-Synthetic-Security-Benchmark-v1.0 (Development Benchmark, Synthetic Data)"`).

### B. `data/benchmarks/` vs `data/benchmarks_backup/` Discrepancy
Phase 10 evaluation does **not** use `data/benchmarks/` (which holds tiny micro-subsets); it uses `data/benchmarks_backup/`. Byte/count audit proves they differ sharply:

| Benchmark | `data/benchmarks/` (`train/val/test`) | `data/benchmarks_backup/` (`train/val/test`) | Exact `target_query` Split Leakage |
| :--- | :---: | :---: | :--- |
| `adversarial_robustness` | `22 / 4 / 4` (`30` total; **8 exact doc dups in train, 2 in val**) | `174 / 36 / 40` (`250` total; `0` doc dups) | **`5`** across train/val/test (`backup`); **`2`** train/test (`benchmarks`) |
| `knowledge_poisoning` | `14 / 2 / 4` (`20` total) | `104 / 22 / 24` (`150` total) | **`3`** across train/val/test (`backup`); **`2`** train/test (`benchmarks`) |
| `clean_rag` | `7 / 1 / 2` (`10` total, from `boolq`) | `70 / 15 / 15` (`100` total, identical SHA-256 to `boolq/custom_splits/`) | `0` |
| `hallucination` | `7 / 1 / 3` (`11` total, from `wice`+`expertqa`) | `7 / 1 / 3` (`11` total; byte-identical `.jsonl` files) | `0` |

Because `custom_security` only has 8 root templates, test queries repeat exact `target_query` strings and template phrasings already seen during Platt/Temperature calibrator training (`train.jsonl`), inflating in-distribution security metrics while providing zero real-world paraphrase diversity.

### C. Offline Adapter Bug (`offline=True` Triggers Network Calls)
Probing all `13` registered adapters via `load_dataset(..., offline=True)` showed that `7` adapters (`natural_questions`, `hotpotqa`, `ms_marco`, `squad`, `halueval`, `llm_aggrefact`, `fineweb`) still execute HuggingFace Hub `HEAD` retry loops (`[Errno 11001] getaddrinfo failed`) before throwing `AcquisitionError: LocalEntryNotFoundError`, instead of short-circuiting immediately when `data/raw/<name>` is empty. Meanwhile `ragtruth` loaded `0` records when pointed at `data/raw/ragtruth/raw_test.jsonl`, while `run_all_external_benchmarks()` loaded `5` records from `data/raw/ragtruth/test.jsonl`.

### D. HuggingFace User Cache Check
Inspection of `~/.cache/huggingface` showed **only one cached artifact**: `datasets--alan-turing-institute--turing-synthetic-radar-dataset` (no NQ, HotpotQA, MS MARCO, HaluEval, RAGTruth, or Qwen checkpoints).

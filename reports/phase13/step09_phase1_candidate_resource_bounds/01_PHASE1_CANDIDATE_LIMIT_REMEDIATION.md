## 1. Problem Statement & Root Cause

In Phase 13 Step 5, Phase 2 candidate extraction was added to catch alphabet-colliding delimiters, and was explicitly bounded with:
```python
for raw in _BASE64_CANDIDATE_RE.findall(text)[:_MAX_B64_CANDIDATES]:
    if len(raw) > _MAX_B64_TOKEN_LEN:
        continue
```
However, the fast path for Phase 1 (clean-boundary standard Base64 tokens) was left untouched:
```python
for match in _BASE64_TOKEN_RE.findall(text):
    if match not in seen:
        seen.add(match)
        tokens.append(match)
```
This created two critical vulnerabilities:
1. **Candidate Flooding:** If an attacker supplied 10,000 clean Base64 tokens, Phase 1 evaluated all 10,000 tokens, degrading latency and consuming unbounded processing cycles.
2. **Intermediate List Materialization:** `re.findall()` eagerly constructs an in-memory Python list containing every match string before the `for` loop begins execution, risking heap bloat under adversarial query streams.
3. **Missing Token Length Guard:** Unlike Phase 2, Phase 1 did not check `len(match) > _MAX_B64_TOKEN_LEN = 8192`.

---

## 2. Implementation Details

In [src/trustrag/guardrails/input_guardrail.py](file:///home/aditya/rags/TrustRag-phase11/src/trustrag/guardrails/input_guardrail.py), Phase 1 extraction was refactored to use lazy iteration via `.finditer()` with strict candidate and length bounding:

```python
    # Phase 1: strict extraction (backward compatible, fast path) bounded to _MAX_B64_CANDIDATES
    phase1_count = 0
    for match_obj in _BASE64_TOKEN_RE.finditer(text):
        if phase1_count >= _MAX_B64_CANDIDATES:
            break
        match = match_obj.group(0)
        phase1_count += 1
        if len(match) > _MAX_B64_TOKEN_LEN:
            continue
        if match not in seen:
            seen.add(match)
            tokens.append(match)
```

### Architectural Benefits:
1. **Zero Intermediate Allocation:** `.finditer()` yields match objects on demand without materializing intermediate lists.
2. **Strict Upper Bound:** Once 64 candidates have been inspected (`phase1_count >= 64`), the loop breaks immediately.
3. **Length Safety:** Any individual candidate exceeding 8,192 characters is skipped prior to downstream processing.

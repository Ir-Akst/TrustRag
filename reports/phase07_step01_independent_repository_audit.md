## 4. Critical Audit Observations (Code vs Architecture Claims)

1. **Test Pass != Research Parity:** Passing `338 passed, 2 deselected` tests proves deterministic invariants and heuristic edge cases work on curated fixtures. It provides **zero evidence** of neural NLI accuracy, 4B SLM hallucination detection (84.0%/75.7%), RSB 13-attack defense, or FilterRAG SLM filtering.
2. **Default Runtime Degradation:** In `configs/base.yaml`, `perplexity_backend=disabled` (F1 dead), `embedding_norm_reference_policy=require_configured` with no configured stats (F2 dead under default `TrustAwareRetriever` path), `provenance_priors={}` (F6 `UNKNOWN` on unlabeled docs), `enable_freq_density=false`, `generation.mode=extractive` (no generative LLM), and `srm.backend=disabled` (`DeterministicFallbackBackend` only). Thus default end-to-end execution relies strictly on TF-IDF (`F3`), regex/obfuscation (`F4`), lexical/numeric conflict (`F5`), heuristic G3, and rule fallback SRM.
3. **Down-weighting vs Fail-Closed Pre-Gen Quarantine Conflict:** `TrustAwareRetriever` intentionally caps removal at `floor(K/2)` and down-weights remaining docs (matching Paper B §6.2), **yet `TrustRAGPipeline.run` (`L167-208, L291-315`) forcibly quarantines any surviving `POISONED` doc post-retrieval and withholds the entire public output (`abstained=True`, `overall_decision=FLAGGED`)**. This explains prior Phase 06 clean utility loss and guarantees zero generative re-answering (`Ê`) on mixed candidate pools.
4. **Benchmark Shrinkage Discovery (Audited in Step 03):** While `data/benchmarks_backup/` stores `clean_rag=100`, `knowledge_poisoning=150`, `adversarial_robustness=250`, current `data/benchmarks/` holds only `clean_rag=10`, `knowledge_poisoning=20`, `adversarial_robustness=30`, `hallucination=11` — creating an acute risk of misleading Phase 06 vs current-split comparisons unless explicitly separated in Steps 03–04.
